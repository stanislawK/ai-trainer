# ADR 0013 — Testing and quality

| | |
|---|---|
| Status | Accepted |
| Date | 2026-09-16 |
| Related | PRD-0001 (all acceptance criteria), ADR-0001, ADR-0002, ADR-0009 |

## Context

The workflow is TDD (ADR-0001): each ticket's acceptance criteria become tests before code. AI features are non-deterministic, so tests must be deterministic and quality measurement belongs to evals (ADR-0009).

## Decision

- **TDD:** red → green → refactor. Every ticket AC maps to at least one named test.
- **Layout:**

  ```
  tests/
    unit/          # domain and application, with fakes for ports
    integration/   # real PostgreSQL, adapters, routes, MCP in-memory client
    e2e/           # pytest-playwright against the running compose stack
  ```

- **pytest** with pytest-asyncio in `auto` mode — one async runner for app, Pydantic AI and FastMCP tests.
- **Integration tests** use a real PostgreSQL — the `docker compose` Postgres (decided at #3, see Consequences), with each test isolated.
- **LLM code:** agents run with Pydantic AI `TestModel` / `FunctionModel` through `agent.override`, and real model requests are disabled globally (`models.ALLOW_MODEL_REQUESTS = False` in `conftest.py`).
- **MCP:** FastMCP's in-memory `Client(server)`.
- **E2E:** pytest-playwright specs, committed, against the running compose stack, with external services (OpenRouter, Google) mocked at the API boundary.
- **Coverage:** pytest-cov; 100% line coverage on the modules a ticket touches. The global floor only goes up.
- **Gates on every push and PR (GitHub Actions):** `ruff check`, `ruff format --check`, `mypy --strict`, `pytest` (unit + integration), the import-boundary check (ADR-0003), and the OpenAPI drift check. E2E joins CI once the first spec exists.
- **OpenAPI:** the snapshot at `docs/api/openapi.json` is regenerated by a script and never hand-edited; CI fails if it drifts.

### Invariants

1. No test calls a real model or external service.
2. Fakes implementing ports are preferred over `mock.patch`.
3. A test is never weakened to make it pass; a wrong test is fixed with a stated reason.
4. Every repository and every user-facing route has a tenancy test (G1).
5. Real-model quality is measured by evals (ADR-0009), not by pytest.

## Consequences

- Skills `/run-tdd` and `/coverage` run this loop; `.claude/rules/tests.md` carries the invariants.
- M0 wires CI, the async runner, the DB fixture and the OpenAPI script.
- Integration tests use the `docker compose` Postgres, decided at #3: they read `DATABASE_URL` from `.env`/the environment like the app does, so `docker compose up -d db` (or the full stack) must be running before `uv run pytest tests/integration`. No testcontainers dependency. CI (#4) runs its own Postgres service the same way, not testcontainers either.
- Warning-filter gotcha, found at #3: `starlette` 1.6.0's `TestClient` imports the deprecated `anyio.abc.BlockingPortal` alias at import time, which this project's `filterwarnings = ["error"]` (ADR-0013) turns into a hard collection error the first time any test imports `fastapi.testclient` or `starlette.testclient` — an upstream bug, not ours, with no fixed release yet. `pyproject.toml`'s `filterwarnings` carries one narrowly-scoped `ignore` for that exact message/module; re-check whether it's still needed next time `starlette` is upgraded.
- CI tooling gotcha, found at #4: `astral-sh/setup-uv`'s `version-file: uv.lock` input only resolves a version when uv itself is a locked dependency (a `[[package]] name = "uv"` entry, from `uv add --dev uv` or similar) — it does not fall back to "latest" like the no-input default path does, so pointing it at a `uv.lock` with no such entry throws `Could not determine uv version from file: uv.lock` and fails the job before any check runs. This project pins uv only in the `Dockerfile` (ADR-0002), not as a project dependency, so `.github/workflows/ci.yml` pins the `setup-uv` step with an explicit `version: "0.11.28"` matching the Dockerfile instead.
